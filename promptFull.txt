Estructura de respuestas API:

```javascript

  success: true,
  data: { ... }, // Datos de respuesta

```

Respuesta de error:
```javascript
{

  code: number, // Código de error HTTP
  message: string, // Mensaje de error

```

Seguridad

Autenticación:
- Sistema: JWT (JSON Web Tokens) - Se utiliza JWT en lugar de sesiones tradicionales
- Razón: Mejor para SPA, stateless, escalable, funciona bien con WebSockets
- Hash de contraseñas: bcrypt con 10 salt rounds
- Duración del token de acceso: 7 días
- Refresh tokens: NO se implementan (los tokens de 7 días son suficientes para este sistema)
- Almacenamiento: Los tokens se almacenan en el cliente (localStorage o sessionStorage)
- Verificación: El token se verifica en cada request mediante middleware

Bibliotecas necesarias:
- jsonwebtoken: Para crear y verificar tokens JWT
- bcrypt: Para hashear contraseñas

Estructura del token JWT:
- Payload contiene: { userId, role, email, iat, exp }
- Algoritmo: HS256
- Secret: Variable de entorno JWT_SECRET (mínimo 32 caracteres)

Middleware de autenticación:
- authenticateToken: Middleware que verifica el JWT en el header Authorization (formato: "Bearer <token>")
  * Si el token es válido: agrega req.user con { userId, role, email }
  * Si el token es inválido o expirado: retorna 401 Unauthorized
- authorizeRole: Middleware que verifica que el usuario tenga el rol requerido
  * Roles disponibles: 'Admin', 'Profesor', 'Tutor', 'Estudiante'
  * Uso: authorizeRole(['Admin', 'Profesor']) - permite acceso solo a esos roles
  * Si no tiene el rol: retorna 403 Forbidden

Endpoints de autenticación:
- POST /api/auth/register: Registro de nuevo usuario
  * Body: { email, password, role, grado, nombre }
  * Validación: express-validator (email válido, password mínimo 8 caracteres, role válido)
  * Retorna: { token, user: { id, email, role, grado } }
- POST /api/auth/login: Inicio de sesión
  * Body: { email, password }
  * Validación: express-validator
  * Retorna: { token, user: { id, email, role, grado } }
- GET /api/auth/me: Obtener información del usuario autenticado
  * Requiere: authenticateToken
  * Retorna: { id, email, role, grado, nombre }
- GET /api/auth/verify: Verificar si el token es válido
  * Header: Authorization: Bearer <token>
  * Retorna: { valid: true/false, user: {...} si es válido }

Otras medidas de seguridad:
- Validación de datos: express-validator en todos los endpoints
- CORS: Configurado para permitir solo el origen del frontend
- Rate limit: express-rate-limit (10 requests por 10 minutos por IP)
- Variables de entorno: JWT_SECRET, DB_*, CORS_ORIGIN, PORT

Algoritmo de Emparejamiento (matching):
- Ubicación: utils/matching.js
- Función: matchTutorToGroup(groupId, materia, fecha, horaInicio, horaFin)
- Criterios de matching (con pesos):
  * Grado del tutor (peso: 30%): Mismo grado = 100 puntos, grado superior = 80 puntos
  * Materia de especialidad (peso: 25%): Coincide materia = 100 puntos
  * Disponibilidad (peso: 25%): Disponible en fecha/hora = 100 puntos
  * Rating promedio (peso: 20%): 5 estrellas = 100 puntos, escala lineal
- Fórmula de scoring:
  * score = (grado_score * 0.30) + (materia_score * 0.25) + (disponibilidad_score * 0.25) + (rating_score * 0.20)
- Priorización:
  1. Score total (mayor a menor)
  2. En caso de empate: Mayor rating promedio
  3. En caso de empate: Mayor número de sesiones completadas
  4. En caso de empate: Más reciente (última sesión)
- Validaciones:
  * Verificar que tutor no tenga conflicto de horario
  * Verificar que tutor tenga disponibilidad configurada
  * Verificar que tutor tenga la materia en sus especialidades
  * Verificar que grado del tutor sea igual o superior al del grupo
- Retorna: Array de tutores ordenados por score (mejor match primero)
